# Документация по данным игры «The City»

Все игровые данные хранятся в JSON-файлах в папке `data/`. Этот документ описывает структуру каждого файла и назначение полей.

---

## Модель гекса: terrain + cover

С 2026-08 рельеф и растительность разделены на два независимых поля:

| Поле | Описание | Примеры |
|---|---|---|
| `terrain` | **Рельеф** — базовый тип местности | `"plain"`, `"hill"`, `"mountain"` (в будущем: `desert`, `swamp`…) |
| `cover` | **Покров** — растительность поверх рельефа | `"none"`, `"sparse_forest"`, `"forest"` (в будущем: хвойный/лиственный/тайга/джунгли) |

**Лес больше НЕ является отдельным типом местности.** Гекс «равнина с лесом» — это `terrain: "plain"` + `cover: "forest"`.

### Отрисовка
1. Сначала рисуется иконка/текстура `terrain` (поле `terrain_icon`).
2. Поверх — полупрозрачный оверлей `cover` (иконка; если иконки нет — цветной полигон с `alpha`).
3. Ресурс / улучшение / прогресс-бары рисуются поверх всего.

### Вырубка леса
Вырубка леса = `cover` → `"none"`. В `special_actions.json` для этого используется `action_type: "cover"`:
- применимо, если `cover` гекса входит в `source_cover` и на гексе **нет** ресурса и улучшения;
- при завершении меняется только `cover`, рельеф/ресурс/улучшение не трогаются.

## Разведение животных и растений (схема `crop_bred`)

В `tile_data` есть **два независимых поля** для ресурсов на гексе:

| Поле | Когда появляется | Когда очищается |
|---|---|---|
| `resource` | Природный ресурс, заданный генератором карты или появившийся после изучения технологии (`tech_required`). Поле — постоянное, не зависит от улучшения | Только специальными действиями (например, снос) или перезаписью вручную |
| `crop_bred` | Разводимое животное/растение, выставленное при постройке пастбища/фермы/пасеки на **пустом** гексе | Сносится вместе с улучшением (через спец-действие «Снос улучшения»); заменяется при постройке новой фермы/пастбища на этом гексе |

### Поведение постройки улучшения

В `main_map._on_build_completed` (`scripts/main_map.gd`) сценарий зависит от того, был ли на гексе природный ресурс:

1. **`tile.resource != null`** (уже был природный ресурс) — ставим улучшение для его добычи. `tile.resource` сохраняется, `tile.crop_bred` остаётся `null`. Это случай «улучшение существующего ресурса» (например, шахта на минерале, ферма на природной пшенице).
2. **`tile.resource == null`** (гекс был пустой) — игрок разводит одомашненный вид. Пишем `id` животного/растения в `tile.crop_bred`, `tile.resource` НЕ трогаем (остаётся `null`). Это случай «построили пастбище на пустом гексе и завели там коров».

### Эффективный ресурс

Подсистемам (производство, тултипы, отрисовка, прогресс-бары исследования) нужен только один id — «что вообще производится на этом гексе». Для этого в `scripts/map_helpers.gd` есть хелпер:

```gdscript
MapHelpers.get_effective_resource(tile)
```

Возвращает `tile.resource` если оно задано, иначе `tile.crop_bred`, иначе пустую строку. Используйте его во всех подсистемах, которые хотят «знать, что производится» на гексе, не задумываясь о природе ресурса.

### Наследование качества

Когда игрок разводит новое животное/растение на пустом гексе, качество определяется так (`scripts/main_map.gd: _on_build_completed`, ветка `else`):

1. Сначала ищем на карте уже одомашненный экземпляр этого же вида — гекс, где `improvement != null` и (`resource == target_res_id` ИЛИ `crop_bred == target_res_id`).
2. Если такой есть и у него задано качество — наследуем («исключительное порождает исключительное»).
3. Иначе — генерируем случайно через `GameData.roll_quality()`.

Поиск по обоим полям (`resource` и `crop_bred`) реализован в `MapHelpers.find_domesticated_quality`.

### Удаление разведения

Снос улучшения (`action_type: "demolish"` в `special_actions.json`) на гексе с `crop_bred`:
- `tile.improvement = null`
- `tile.crop_bred = null`
- `tile.resource` **не трогается** (его на этом гексе и не было — это разведение)

После сноса гекс снова становится «пустым» — на нём можно построить пастбище/ферму для другого вида.

### `data/resources/*.json` — ресурсы на карте

Файлы:
- `resources/minerals.json` — минералы и камни
- `resources/animals.json` — животные
- `resources/plants/food_plants.json` — пищевые растения
- `resources/plants/fruit_plants.json` — плодовые растения
- `resources/plants/textile_plants.json` — технические (текстильные) культуры
- `resources/plants/flowers.json` — цветы

Корневой ключ: `resources` (массив объектов).

| Поле | Тип | Обязательность | Описание | Пример |
|---|---|---|---|---|
| `id` | string | ✅ | Уникальный идентификатор ресурса | `"wheat_field"` |
| `name` | string | ✅ | Отображаемое название | `"Пшеница"` |
| `type` | string | ✅ | Тип сущности. Для ресурсов на карте всегда `"raw"` | `"raw"` |
| `category` | string | ✅ | Категория (см. `categories.json`) | `"plants"`, `"animals"`, `"minerals"` |
| `group` | string | ✅ | Группа для бонусов за разнообразие (см. `groups.json`). Может быть пустой строкой | `"food_plants"`, `"meat_animals"`, `""` |
| `subgroup` | string | ✅ | Подгруппа для бонусов за разнообразие (см. `groups.json`). Может быть пустой строкой | `"cereals"`, `"cattle"`, `""` |
| `tech_required` | string | ⬜ | **Технология, открывающая появление ресурса на карте.** Пока не изучена — ресурс не спавнится. Отсутствует у дикоросов (`wild_food`) | `"farming"` |
| `allowed_terrain` | array\<string\> | ✅ | **Рельефы**, на которых ресурс может заспавниться (см. `terrains.json`) | `["plain", "hill"]` |
| `allowed_cover` | array\<string\> | ✅ | **Покровы**, на которых ресурс может заспавниться (см. `covers.json`). Логика — И с `allowed_terrain` | `["none", "sparse_forest", "forest"]` |
| `spawn_conditions` | array\<array\<object\>\> | ⬜ | **Дополнительные условия спавна ресурса.** Массив групп условий, объединённых И/ИЛИ (см. подраздел ниже). Если условия не выполнены — ресурс исключается из спавна | `[ [ { "type": "near_river", "chance": 100 } ] ]` |
| `improved_by` | string \| null | ✅ | ID улучшения, которое нужно построить для добычи ресурса (см. `improvements.json`). `null` — ресурс не требует улучшения (например, дикоросы) | `"farm"`, `null` |
| `produces` | object | ✅ | Что даёт ресурс: `{ "продукт": количество }` | `{ "wheat": 1, "feed": 12 }` |
| `icon` | string | ✅ | Имя файла иконки в `icons/` | `"wheat.png"` |
| `color` | array\<number\> | ✅ | Цвет-заглушка RGB `[r, g, b]` (0–255), используется если иконка не найдена | `[218, 165, 32]` |
| `feed_consumption` | number | ⬜ | **Только для животных.** Потребление корма в единицу времени | `10` |
| `time_to_mature` | number | ⬜ | **Только для животных.** Время до взросления | `60.0` |

> **Важно:** `tech_required` используется **только** в файлах ресурсов. Для зданий, улучшений, продуктов и рецептов используется `unlock_tech`.

### `tech_reveal` — скрытые ресурсы (подземные ископаемые)

`tech_reveal` — необязательное строковое поле в `data/resources/*.json`. Смысл: ресурс **существует на карте с самого старта**, но игрок его **не видит**, пока не изучена указанная технология. После изучения — ресурс становится видимым, как обычный (с учётом разведки/покупки зоны).

| Поле | Когда | Что делает |
|---|---|---|
| `tech_required` | Постройка улучшения для добычи | Без изученной технологии улучшение (`farm`/`mine`/...) недоступно в UI. Сам ресурс при этом виден на карте. |
| `tech_reveal` | Просмотр самого ресурса на карте | Без изученной технологии ресурс **скрыт от игрока**: не отображается в тултипе, не упоминается в отчёте разведчиков, не показывается в контекстном меню, на гексе нет иконки ресурса. После изучения — становится полностью видимым, как обычный ресурс. |

**Связь двух полей.** У большинства ресурсов только `tech_required`: они видны сразу, но добывать можно только после соответствующей технологии. У «подземных» ресурсов (глубинные металлы, редкие руды) заполняется **оба** поля. Типичная пара для железа:

```json
"tech_reveal": "mining",            // игрок учится различать руду в горах
"tech_required": "metal_processing" // игрок учится её добывать и плавить
```

Пока не изучен `mining`, железо «невидимо»: разведчики сообщают «Ресурсы: нет», тултип не показывает ресурс, иконки на гексе нет. Изучил `mining` — увидел руду в горах; исследовал `metal_processing` — смог поставить шахту и начать добычу.

**Конфликт с улучшением.** Если к моменту обнаружения `tech_reveal`-ресурса на этом гексе уже стоит улучшение для другого ресурса (например, на холме с железом игрок поставил пастбище с овцами), рисуется **красный треугольник с «!»**:

- Старое улучшение **не сносится автоматически**, его производство продолжается.
- В тултипе: «Здесь обнаружено: \<ресурс\>» и «Снесите текущее улучшение, чтобы построить \<новое_улучшение\>» (имя улучшения подставляется из `improved_by` ресурса, не хардкод).
- Треугольник появляется **только когда `tech_reveal` уже изучен** — до этого ни треугольника, ни упоминания ресурса нет.

**Гарантии спавна в стартовой области.** Чтобы игрок не оказался в ситуации «изучил X, а в зоне ничего нет», для стартовой области «Кольцо + Регион» гарантируется наличие минимум одного представителя каждой ключевой категории (через `MapHelpers.ensure_minimum_resource`, который выбирает **случайный** id из подходящих):

| Гарантия | Фильтр | Границы | Зачем |
|---|---|---|---|
| Металл | `{ "category": "metals" }` | Кольцо + Регион | Узнал про металлы — есть что добывать. При добавлении новых металлов (медь, олово, золото…) достаточно указать им `tech_reveal` — гарантия сработает автоматически. |
| Мясное животное | `{ "category": "animals", "group": "meat_animals" }` | Кольцо + Регион | После `animal_husbandry` — есть с кого начать скотоводство. |
| Стройматериал | `{ "category": "minerals", "subgroup": "construction_materials" }` | Кольцо + Регион | После `mining`/`masonry` — есть что добывать для стройки. |

**Пищевое растение** гарантируется отдельно через `_ensure_food_plant` и остаётся **только** в стартовом Кольце (не в Регионе): игрок должен иметь возможность поставить ферму сразу, без разведки и покупки чанков.

При добавлении новых категорий (например, руды для `metalurgy`) достаточно добавить в `_initialize_map` ещё один вызов `_ensure_minimum_resource({"category": "...", "group": "...", "subgroup": "..."})` с нужным фильтром.

#### Дополнительные условия спавна (`spawn_conditions`)

Поле `spawn_conditions` позволяет задать **дополнительные условия**, при которых сырьевой ресурс (`"type": "raw"`) может появиться на карте. Оно проверяется **параллельно** с `allowed_terrain`, `allowed_cover` и `tech_required`: ресурс заспавнится, только если выполнены И рельеф, И покров, И технология, И условия спавна.

**Формат** — массив групп условий, объединённых логикой **И/ИЛИ** (аналогично `prerequisites` технологий):

```json
"spawn_conditions": [
  [ { "type": "near_river", "chance": 100 } ]
]
```

- **Внешний массив** — группы условий, объединённые **ИЛИ**: достаточно, чтобы выполнилась хотя бы одна группа.
- **Внутренний массив** — условия группы, объединённые **И**: должны выполниться все условия группы.
- Каждое условие — объект:
  - `type` — тип условия (см. список ниже);
  - `chance` (число 0–100) — **вероятность активации** ресурса. Если случайный бросок не попадает в шанс, группа считается невыполненной.

**Доступные типы условий:**

| Тип | Описание |
|---|---|
| `near_river` | Гекс имеет **общее ребро** с рекой (у гекса заполнены `river_edges`). Реки генерируются во время создания карты, поэтому проверка корректно работает и при динамическом спавне ресурса после изучения технологии |

**Поведение при невыполнении условий:**

1. Во время спавна (на старте игры и при динамическом спавне по технологии) для ресурса с `spawn_conditions` сначала «бросается шанс» `chance`. Если шанс не выпал — ресурс **исключается** из числа ресурсов, которые могут появиться на карте.
2. Затем ищутся подходящие гексы, удовлетворяющие одновременно `allowed_terrain`, `allowed_cover` и геометрическим условиям групп (например, для `near_river` — только гексы, соседствующие с рекой).
3. Если подходящих гексов не нашлось (например, река не проходит рядом с подходящей территорией) — ресурс **не появляется**. В случае исследования технологии игрок увидит сообщение «Похоже, в вашем регионе X отсутствует».

**Пример — глина (`clay_deposit`):** спавнится только в гексе с разрешенным типом местности (`"allowed_terrain": ["plain"]`), имеющим общее ребро с рекой, со 100-процентной вероятностью:

```json
"spawn_conditions": [ [ { "type": "near_river", "chance": 100 } ] ]
```

#### Универсальное условие по типу местности (`terrain`)

Помимо `near_river`, существует универсальное условие спавна по **типу местности**:

```json
"spawn_conditions": [ [ { "type": "terrain", "terrain_id": "soda_lake", "chance": 100 } ] ]
```

- `type: "terrain"` — ресурс может появиться только на гексах, у которых `terrain == terrain_id`.
- Это условие используется для ресурсов, добываемых на **уникальной местности** (например, сода на содовом озере `soda_lake`).
- Ресурсы с таким условием спавнятся на подходящих гексах в любой части карты (включая за пределами стартового Кольца/Региона), потому что уникальная местность может находиться далеко.

---

### Уникальные типы местности (поле `unique: true`)

Некоторые типы местности не являются «базовым рельефом» (равнина, холмы, горы, озёра), которые участвуют в алгоритме Вороного. Вместо этого они размещаются на карте **отдельно и в единственном экземпляре**. Такие типы помечаются в `data/terrains.json`:

```json
{
  "id": "soda_lake",
  "name": "Содовое озеро",
  "color": [200, 220, 255],
  "move_cost": 999,
  "expansion_cost": 200,
  "unique": true,
  "cluster_size": 3,
  "cover_chance": { "none": 100 }
}
```

**Поведение:**
1. `map_generator.gd.make_terrain_counts()` игнорирует типы с `unique: true` — они **не участвуют** в диаграмме Вороного.
2. Универсальная функция `place_unique_terrains(tile_data, rows, cols, city_row, city_col)` сама итерирует по **всем** уникальным типам местности (`unique: true`) из `data/terrains.json`. Для каждого типа она читает максимальный размер кластера из поля `cluster_size` (дефолт `3`, если поле не задано) и размещает **один связный кластер** размером `1..cluster_size` гексов **за пределами стартового Кольца Влияния**.
3. В `generate_map()` вызывается один раз: `place_unique_terrains(tile_data, rows, cols, city_row, city_col)`. Добавление нового уникального типа в `terrains.json` (с `"unique": true` и `"cluster_size"`) **не требует изменения кода** — функция подхватит его автоматически.

**Отображение:** гексы уникальной местности, находящиеся **за пределами видимого Региона**, отображаются на карте затемнёнными (как неисследованный Регион), без ресурсов/улучшений. Это реализовано в `map_renderer._draw_unique_terrain_hex()` (список гексов хранится в `main_map.unique_terrain_hexes`).

### Пример: Сода (содовое озеро `soda_lake`)

Цепочка:
1. **`terrains.json`** — тип местности `soda_lake` с `"unique": true` и `"cluster_size": 3`.
2. **`map_generator.gd`** — при генерации карты `place_unique_terrains` размещает кластер `soda_lake` (1..`cluster_size` гексов) за пределами Кольца.
3. **`resources/minerals.json`** — ресурс `soda_deposit`:
   - `tech_required: "soda_extraction"` — появляется на карте после изучения технологии.
   - `allowed_terrain: ["soda_lake"]` — только на содовом озере.
   - `spawn_conditions: [ [ { "type": "terrain", "terrain_id": "soda_lake", "chance": 100 } ] ]` — поиск по всей карте.
   - `improved_by: "soda_quarry"` — добывается улучшением «Содовый карьер».
4. **`technologies.json`** — `soda_extraction` («Добыча соды», пререквизит `mining`) открывает и ресурс, и улучшение; от `soda_extraction` зависят `glassmaking` и `soap_making`.
5. **`improvements.json`** — `soda_quarry` («Содовый карьер», `unlock_tech: "soda_extraction"`).

### Уникальная местность с бонусом к производству (`terrain_modifiers`)

Некоторые уникальные типы местности дают **бонус к производству** ресурса, который на них добывается. Например, асфальтовое озеро (`asphalt_lake`) даёт **x2 к битуму**. Бонус реализуется через систему модификаторов в `data/modifiers.json` — блок `terrain_modifiers`.

**Формат `terrain_modifiers`** (массив объектов):

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `terrain_id` | string | Тип местности, на котором действует бонус | `"asphalt_lake"` |
| `resource_id` | string | ID ресурса, к которому применяется бонус | `"bitumen_deposit_asphalt"` |
| `production_multiplier` | number | Множитель производства (перемножается с остальными модификаторами) | `2.0` |

```json
"terrain_modifiers": [
  {
    "terrain_id": "asphalt_lake",
    "resource_id": "bitumen_deposit_asphalt",
    "production_multiplier": 2.0
  }
]
```

**Как это работает:**
1. Модификатор применяется, когда на гексе с `terrain_id` добывается именно `resource_id` (через улучшение).
2. Множитель перемножается с остальными модификаторами (пресная вода, технологии) в `CityData.get_improvement_production_multiplier`.
3. В расширенном тултипе бонус отображается строкой вида `x2.0 (Асфальтовое озеро)`.

**Важно:** бонус привязан к **конкретному ресурсу**, а не к типу местности в целом. Это позволяет иметь на карте одновременно:
- обычный битум (`bitumen_deposit`) на равнине/холмах — x1;
- битум на асфальтовом озере (`bitumen_deposit_asphalt`) — x2.

### Пример: Битум (асфальтовое озеро `asphalt_lake`)

Цепочка:
1. **`terrains.json`** — тип местности `asphalt_lake` с `"unique": true` и `"cluster_size": 3`.
2. **`map_generator.gd`** — при генерации карты `place_unique_terrains` размещает кластер `asphalt_lake` (1..`cluster_size` гексов) за пределами Кольца.
3. **`resources/minerals.json`** — ресурс `bitumen_deposit_asphalt`:
   - `tech_required: "bitumen_extraction"` — появляется на карте после изучения технологии.
   - `allowed_terrain: ["asphalt_lake"]` — только на асфальтовом озере.
   - `spawn_conditions: [ [ { "type": "terrain", "terrain_id": "asphalt_lake", "chance": 100 } ] ]` — поиск по всей карте.
   - `improved_by: "tar_pit"` — добывается тем же улучшением «Смоляная яма», что и обычный битум.
4. **`modifiers.json`** — `terrain_modifiers` с `terrain_id: "asphalt_lake"`, `resource_id: "bitumen_deposit_asphalt"`, `production_multiplier: 2.0`.
5. **`technologies.json`** — `bitumen_extraction` («Добыча битума») открывает и ресурс, и улучшение.
6. **`improvements.json`** — `tar_pit` («Смоляная яма», `unlock_tech: "bitumen_extraction"`).

### Болота и марши

Болото — базовый рельеф (`swamp`), который участвует в алгоритме Вороного наравне с равниной, холмами, озёрами и горами. У болот может быть любой тип покрова: `none`, `sparse_forest`, `forest` или `reeds` (тростник). Конфигурация `terrain_config` в `data/map_config.json` задаёт долю болот на карте (`density`, по умолчанию 5%) и средний размер кластера (`target_cluster`, ограничение сверху — по умолчанию 5 гексов, т.е. болота образуют мелкие разрозненные пятна).

Марши — это пост-обработка рельефа после Вороного в `map_generator.gd`. Вокруг каждого озера `lake` **и каждого моря `sea`** каждый соседний равнинный гекс (`plain`) с шансом ~45% (конст `MARSH_CHANCE`) превращается в болото — так образуется кольцо шириной в 1 гекс вокруг воды. Такой гекс дополнительно помечается временным флагом `_is_marsh`, и при генерации покрова его `cover` принудительно становится `reeds`.

Ресурс « Глина» (`clay_deposit`) в `data/resources/minerals.json` расширен и также может спавниться на болотах: `allowed_terrain` теперь включает `"swamp"`, а `allowed_cover` — `"reeds"`.

### Моря и пляжи

Море (`sea`) и пляж (`beach`) — два новых типа местности, которые **не участвуют** в алгоритме Вороного (не входят в `terrain_config`). Море генерируется как **маска** до Вороного и повторно применяется поверх результата, чтобы Вороной не перезаписал его.

#### Типы местности

| Тип | `move_cost` | `expansion_cost` | `work_cost_mult` | Описание |
|---|---|---|---|---|
| `sea` | `999` (непроходимо) | `0` | `1.0` | Открытая вода. Непроходима для юнитов, но **строибельная** территория (можно ставить рыбацкие лодки и т.п.) |
| `beach` | `1` | `50` | `1.0` | Побережье. Проходимо, обычная строибельная территория |

Оба типа имеют `cover_chance: { "none": 100 }` — покров на них не генерируется.

#### Конфигурация (`data/map_config.json`, блок `sea`)

```json
"sea": {
  "mode": "noise",            // "none" | "edge" | "noise"
  "sea_level": 0.0,
  "noise_strength": 0.35,
  "edge_gradient": 0.4,       // 0 = острова везде, 1 = море строго у краёв
  "city_bump": 0.5,           // гарант стартового континента
  "city_bump_radius": 8,      // гарантирует Кольцо, а не всё окно — берег может быть виден
  "beach": true,
  "sides": [1, 2],            // диапазон [min, max] количества случайных сторон
  "width_min": 4,
  "width_max": 7,
  "max_width": 8              // глобальный предел ширины моря от края карты
}
```

| Поле | Тип | Описание |
|---|---|---|
| `mode` | string | `"none"` — морей нет; `"noise"` (вариант А) — elevation = градиент от края + шум + city_bump, суша = `elevation > sea_level`; `"edge"` (вариант Б) — полоса моря у выбранных сторон, ширина — гладкий 1D-шум |
| `sea_level` | number | Порог «суша/море» для варианта А |
| `noise_strength` | number | Амплитуда шума высот для варианта А |
| `edge_gradient` | number | 0 = острова везде, 1 = море строго у краёв (вариант А) |
| `city_bump` | number | «Холм» высоты вокруг города: гарантирует стартовый континент |
| `city_bump_radius` | number | Радиус гарантированной суши вокруг города (в гексах). Малый радиус (8) гарантирует Кольцо, а не всё окно — берег может быть виден в Регионе |
| `beach` | boolean | `true`: суша, соседняя с морем, становится пляжем (`beach`) |
| `sides` | array\<number\> | Диапазон `[min, max]` количества случайно выбранных сторон света, у которых будет море (`"east"`, `"west"`, `"north"`, `"south"`). `[x,x]` — фиксированное число сторон. `[0,0]` — море не генерируется. Применяется и к `mode: "noise"`, и к `mode: "edge"` |
| `width_min` / `width_max` | number | Для `mode: "edge"`: диапазон ширины полосы моря (в гексах) |
| `max_width` | number | Глобальный предел ширины моря от края карты (в гексах). Ограничивает и вариант А, и вариант Б, чтобы не генерировать/отрисовывать бесконечное море |

#### Генерация

1. **`map_generator.gd`** — `_apply_sea()` вызывается в начале `generate_map` (до Вороного). Строит маску моря по выбранному режиму, помечает гексы временным флагом `_is_sea`, а сушу, соседнюю с морем, — флагом `_is_beach` (если `beach: true`).
2. После Вороного маска **повторно применяется** поверх результата (по флагам `_is_sea` / `_is_beach`), чтобы Вороной не перезаписал море/пляж.
3. **Марши** генерируются и вокруг морей (как вокруг озёр): соседние равнины с шансом ~45% становятся маршами.
4. **Коридор выхода** (`_ensure_outward_corridor`) пробивает море как озеро (море — не препятствие для пробивки), а побережье (`beach`, `move_cost: 1`) — валидный выход.

#### Реки и моря

- **Главные реки** могут впадать в моря так же, как в озёра (устья = озёра + моря).
- **Притоки** не впадают в моря (как и в озёра) — только в главные реки или другие притоки.
- Реки **не текут по морю**: морские гексы и их соседи входят в `restricted_hexes` в `river_manager.gd`.

#### Строительство на море

Море — обычная строибельная территория. Гекс моря входит в Кольцо Влияния (через `in_influence`), и на нём можно строить улучшения (например, рыбацкие лодки) через стандартный механизм. `expansion_cost: 0` означает, что море дёшево/бесплатно осваивается при расширении территории. `work_cost_mult: 1.0` — строительство на море не дороже, чем на равнине.

#### Город

`ensure_city_valid_terrain` (`map_helpers.gd`) гарантирует, что город не окажется на море/пляже: если город сгенерирован/загружен на `sea`/`beach` (или горе/озере), он превращается в равнину.

#### `data/covers.json` — покров (лес)

Покров `reeds` («Тростник») используется принудительно на болотах вокруг озёр (марши) и может выпадать на болотах со случайным покровом.

Используется в `resources/*.json` (поле `allowed_cover`).

Корневой ключ: `covers` (массив объектов).

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `id` | string | Уникальный идентификатор покрова | `"forest"` |
| `name` | string | Отображаемое название (показывается игроку, напр. «Лес») | `"Лес"` |
| `color` | array\<number\> | Цвет-заглушка RGB `[r, g, b]` (0–255) для фолбека | `[34, 139, 34]` |
| `alpha` | number | Непрозрачность оверлея (0.0 – 1.0) | `0.45` |
| `move_cost_bonus` | number | Дополнительная стоимость перемещения от покрова (сейчас 0 — лес не замедляет, как раньше terrain-лес с `move_cost: 1`) | `0` |
| `icons` | array\<string\> | Иконки оверлея в `icons/terrain/` (рисуются поверх terrain; если пусто — цветной полигон) | `["forest_1.png", "forest_2.png", "forest_3.png"]` |

Используется в `resources/*.json` (поле `allowed_cover`).

#### `data/special_actions.json` — спецдействия на карте

Спецдействия — это действия, выполняемые на гексах карты (вырубка леса, сбор дикоросов, снос улучшений и т.п.). Они реализуются через систему труда `build_manager`, но не являются улучшениями.

Корневой ключ: `special_actions` (массив объектов).

| Поле | Тип | Обязательность | Описание | Пример |
|---|---|---|---|---|
| `id` | string | ✅ | Уникальный идентификатор спецдействия | `"clear_forest"` |
| `name` | string | ✅ | Отображаемое название | `"Вырубка леса"` |
| `action_type` | string | ⬜ | Тип действия. `"terrain"` (по умолчанию) — превращает местность; `"cover"` — меняет покров; `"forage"` — сбор ресурса; `"demolish"` — снос улучшения | `"cover"` |
| `source_terrain` | string | ⬜ | Для `action_type: "terrain"`. Тип местности, к которому применимо действие (см. `terrains.json`) | `"swamp"` |
| `source_cover` | array\<string\> | ⬜ | Для `action_type: "cover"`. Покровы, к которым применимо действие (см. `covers.json`). Действие недоступно, если на гексе есть ресурс или улучшение | `["forest", "sparse_forest"]` |
| `target_resource` | string | ⬜ | Для `action_type: "forage"`. ID ресурса, который собирается действием | `"wild_food"` |
| `result_terrain` | string | ✅ | Тип местности, в который превращается исходная. Значение `"dont_change"` означает, что тип местности не меняется | `"plain"`, `"dont_change"` |
| `result_cover` | string | ⬜ | Для `action_type: "cover"`. Покров, который будет установлен после завершения (например, `"none"` — вырубка леса) | `"none"` |
| `work_cost` | number | ✅ | Стоимость в труде | `22` |
| `yield` | object | ⬜ | Для `action_type: "forage"`. Что даёт действие: `{ "продукт": [мин, макс] }` — случайное количество в диапазоне | `{ "foraged_food": [5, 10] }` |
| `unlock_tech` | string | ⬜ | Технология, открывающая действие. Пока не изучена — в контекстном меню показывается пункт «Изучить X» | `"metal_processing"` |

**Типы действий (`action_type`):**

- `"terrain"` (по умолчанию) — превращает один тип местности в другой. Применимо, если гекс имеет `source_terrain` и на нём нет улучшения. Пример: осушение болот.
- `"cover"` — меняет покров гекса (`source_cover` → `result_cover`). Применимо, если `cover` гекса входит в `source_cover` и на гексе **нет** ресурса и улучшения (запрет вырубки леса с ресурсом/улучшением). При завершении меняется только `cover`. Пример: вырубка леса.
- `"forage"` — сбор ресурса (например, дикоросов). Применимо, если на гексе есть ресурс `target_resource`. При завершении убирает ресурс и добавляет `yield` на склад. Тип местности не меняется.
- `"demolish"` — снос улучшения. Применимо, если на гексе есть улучшение. При завершении убирает улучшение, ресурс остаётся. Тип местности не меняется.

> **Пример добавления нового спецдействия** (осушение болот): достаточно добавить запись с `"action_type": "terrain"`, `"source_terrain": "swamp"`, `"result_terrain": "plain"` и нужной стоимостью — код менять не нужно.
>
> **Пример сбора дикоросов** (встроен в игру): `"action_type": "forage"`, `"target_resource": "wild_food"`, `"result_terrain": "dont_change"`, `"yield": { "foraged_food": [5, 10] }`.
>
> **Пример сноса улучшения** (встроен в игру): `"action_type": "demolish"`, `"result_terrain": "dont_change"`.

## Схема мира: Кольцо, Регион, Карта и Эпохи

### Терминология

| Термин | Описание |
|---|---|
| **Карта мира** | Вся гексовая карта (`map_rows × map_cols`). Генерируется полностью при старте новой игры: рельеф, покров, ресурсы и реки для всех 60×60 (или сколько будет указано в map_config.json) гексов сразу. |
| **Кольцо Влияния** | Прямоугольная область вокруг города, которая принадлежит игроку с самого начала. Размер задаётся в `data/map_config.json`. |
| **Регион** | Видимая/доступная полоса гексов вокруг Кольца (ширина `region_width`). Гексы Региона можно разведывать и покупать. |
| **Туман войны** | Все гексы за пределами Кольца + Региона существуют в данных, но **не отображаются** на карте и недоступны для взаимодействия. |

### Конфигурация размеров (`data/map_config.json`)

```json
{
  "map_config": {
    "map_rows": 60,        // Вся карта: ряды (гексы)
    "map_cols": 60,        // Вся карта: колонки (гексы)
    "start_ring_rows": 7,   // Стартовое Кольцо Влияния: ряды
    "start_ring_cols": 9,   // Стартовое Кольцо Влияния: колонки
    "region_width": 2,      // Ширина Региона вокруг Кольца (в гексах)

    // --- Плотности и кластеры типов местности ---
    // target_cluster — глобальный размер кластера в гексах (запасное для типов без собственного).
    // terrain_config — для каждого типа: density (доля центров) + target_cluster
    //   (ограничение сверху: centers ≤ area / target_cluster).
    "target_cluster": 22,
    "terrain_config": {
      "plain":    { "density": 0.40, "target_cluster": 22 },
      "hill":     { "density": 0.25, "target_cluster": 30 },
      "lake":     { "density": 0.10, "target_cluster": 50 },
      "mountain": { "density": 0.20, "target_cluster": 25 },
      "swamp":    { "density": 0.05, "target_cluster": 5 }
    },

    // --- Генерация рек ---
    "num_main_rivers": 3,      // Количество главных рек
    "num_tributaries": 5,      // Количество притоков
    "min_river_length": 8,     // Минимальная длина главной реки (в точках пути)
    "min_tributary_length": 4  // Минимальная длина притока (в точках пути)
  }
}
```

Файл загружается тем же загрузчиком, что и остальные данные (`data_loader.gd`), поэтому поддерживает комментарии `//` и `/* */`.

### Генерация рек (речная система)

Реки генерируются в `river_manager.gd` при старте новой игры (после генерации рельефа и ресурсов). Схема — **речная система** из главных рек и притоков:

- **Главные реки** — исток в горах, устье в озере **или море**. Не пересекаются друг с другом (A* идёт с запретом на занятые вершины).
- **Притоки** — исток в горах (или холмах, если гор мало), впадают в главные реки или в другие притоки (точка слияния). Притоки **не впадают в озёра и моря** (их вершины исключаются из точек слияния).
- **Гарантия стартовой области** — хотя бы одна река всегда проходит через стартовую область «Кольцо + Регион». Если после генерации главных рек ни одна не пересекла область, генерируется дополнительная главная река через промежуточную вершину внутри области (гора с одной стороны → вершина в области → озеро/море с другой стороны).

Количество рек и минимальные длины задаются в `data/map_config.json` (см. выше). Формат данных рек (`Array of Array of Vector2`) не изменился, поэтому рендеринг, сохранение/загрузка и бонусы у рек работают как раньше.

### Абсолютные координаты и окно

- Координаты гексов — **абсолютные** в пределах всей карты (`0..map_rows-1`, `0..map_cols-1`).
- Город всегда находится в **центре карты** (`city_row = map_rows / 2`, `city_col = map_cols / 2`).
- Границы Кольца и Региона пересчитываются динамически относительно города:
  - `influence_start/end_row/col` — абсолютные границы Кольца;
  - `region_start/end_row/col` — абсолютные границы видимого окна «Кольцо + Регион».
- **Рендеринг, ввод, разведка, покупка, производство и рабочие работают только в пределах окна.** Гексы за окном не отрисовываются (туман войны).

### Переход в следующую эпоху

Кнопка **«Перейти в следующую эпоху»** в дебаг-меню (F9) выполняет:

1. Весь текущий (некупленный) Регион **моментально и бесплатно** исследуется.
2. Весь текущий Регион **моментально и бесплатно** покупается/присоединяется (`in_influence = true`).
3. Бывшие Кольцо + Регион становятся **новым Кольцом Влияния**.
4. Вокруг нового Кольца формируется **новый Регион той же ширины** (`region_width`).
5. Гексы за пределами нового Кольца + Региона по-прежнему скрыты туманом войны.

Реализация: `main_map.advance_to_next_era()`.

### Сохранение состояния мира

В сейв сохраняется блок `map_state`, содержащий размеры карты, текущие размеры Кольца/Региона и номер эпохи. При загрузке состояние восстанавливается до построения `tile_data`.
