# Документация по данным игры «The City»

Все игровые данные хранятся в JSON-файлах в папке `data/`. Этот документ описывает структуру каждого файла и назначение полей.

---

## Технологии: два способа открыть контент

В игре есть **два разных поля**, которые связывают контент с технологиями. Их легко перепутать, но они отвечают за разные вещи:

| Поле | Где используется | Что делает |
|---|---|---|
| `tech_required` | Только **ресурсы** (`data/resources/*.json`) | Ресурс **не появляется на карте**, пока технология не изучена. При изучении технологии ресурс **спавнится** на карту. |
| `unlock_tech` | **Здания, улучшения, продукты, рецепты** | Объект **существует в данных**, но **недоступен игроку** (нельзя построить / произвести / использовать), пока технология не изучена. |

> **Правило-запоминалка:**
> - `tech_required` — «ресурс **появится в мире**»
> - `unlock_tech` — «действие **станет доступно**»

### Поведение заблокированного ресурса (`tech_required`)

1. Пока технология не изучена, ресурс **не генерируется на карте** (`map_generator.gd` пропускает его).
2. При изучении технологии ресурс **появляется на карте** (`CityData.spawn_resource_on_tech_research`).
3. В контекстном меню гекса с таким ресурсом показывается пункт **«Изучить X (наука: N)»**, который запускает исследование нужной технологии.

### Поведение недоступного объекта (`unlock_tech`)

1. Здание нельзя построить, пока технология не изучена.
2. Рецепт скрыт из списка доступных в здании.
3. Продукт не отображается как доступный на складе.
4. Улучшение (ферма, шахта и т.д.) нельзя построить на тайле.

## Модель гекса: terrain + cover

С 2026-08 рельеф и растительность разделены на два независимых поля:

| Поле | Описание | Примеры |
|---|---|---|
| `terrain` | **Рельеф** — базовый тип местности | `"plain"`, `"hill"`, `"mountain"` (в будущем: `desert`, `swamp`…) |
| `cover` | **Покров** — растительность поверх рельефа | `"none"`, `"sparse_forest"`, `"forest"` (в будущем: хвойный/лиственный/тайга/джунгли) |

**Лес больше НЕ является отдельным типом местности.** Гекс «равнина с лесом» — это `terrain: "plain"` + `cover: "forest"`.

### Отрисовка
1. Сначала рисуется иконка/текстура `terrain` (поле `terrain_icon`).
2. Поверх — полупрозрачный оверлей `cover` (иконка; если иконки нет — цветной полигон с `alpha`).
3. Ресурс / улучшение / прогресс-бары рисуются поверх всего.

### Вырубка леса
Вырубка леса = `cover` → `"none"`. В `special_actions.json` для этого используется `action_type: "cover"`:
- применимо, если `cover` гекса входит в `source_cover` и на гексе **нет** ресурса и улучшения;
- при завершении меняется только `cover`, рельеф/ресурс/улучшение не трогаются.

| `spawn_conditions` | array\<array\<object\>\> | ⬜ | **Дополнительные условия спавна ресурса.** Массив групп условий, объединённых И/ИЛИ (см. подраздел ниже). Если условия не выполнены — ресурс исключается из спавна | `[ [ { "type": "near_river", "chance": 100 } ] ]` |

| `produces` | object | ✅ | Что даёт ресурс: `{ "продукт": количество }` | `{ "wheat": 1, "feed": 12 }` |

| `color` | array\<number\> | ✅ | Цвет-заглушка RGB `[r, g, b]` (0–255), используется если иконка не найдена | `[218, 165, 32]` |
| `feed_consumption` | number | ⬜ | **Только для животных.** Потребление корма в единицу времени | `10` |

#### Дополнительные условия спавна (`spawn_conditions`)

Поле `spawn_conditions` позволяет задать **дополнительные условия**, при которых сырьевой ресурс (`"type": "raw"`) может появиться на карте. Оно проверяется **параллельно** с `allowed_terrain`, `allowed_cover` и `tech_required`: ресурс заспавнится, только если выполнены И рельеф, И покров, И технология, И условия спавна.

**Формат** — массив групп условий, объединённых логикой **И/ИЛИ** (аналогично `prerequisites` технологий):

```json
"spawn_conditions": [
  [ { "type": "near_river", "chance": 100 } ]
]
```

- **Внешний массив** — группы условий, объединённые **ИЛИ**: достаточно, чтобы выполнилась хотя бы одна группа.
- **Внутренний массив** — условия группы, объединённые **И**: должны выполниться все условия группы.
- Каждое условие — объект:
  - `type` — тип условия (см. список ниже);
  - `chance` (число 0–100) — **вероятность активации** ресурса. Если случайный бросок не попадает в шанс, группа считается невыполненной.

**Доступные типы условий:**

| Тип | Описание |
|---|---|
| `near_river` | Гекс имеет **общее ребро** с рекой (у гекса заполнены `river_edges`). Реки генерируются во время создания карты, поэтому проверка корректно работает и при динамическом спавне ресурса после изучения технологии |

**Поведение при невыполнении условий:**

1. Во время спавна (на старте игры и при динамическом спавне по технологии) для ресурса с `spawn_conditions` сначала «бросается шанс» `chance`. Если шанс не выпал — ресурс **исключается** из числа ресурсов, которые могут появиться на карте.
2. Затем ищутся подходящие гексы, удовлетворяющие одновременно `allowed_terrain`, `allowed_cover` и геометрическим условиям групп (например, для `near_river` — только гексы, соседствующие с рекой).
3. Если подходящих гексов не нашлось (например, река не проходит рядом с подходящей территорией) — ресурс **не появляется**. В случае исследования технологии игрок увидит сообщение «Похоже, в вашем регионе X отсутствует».

**Пример — глина (`clay_deposit`):** спавнится только в гексе равнины (`"allowed_terrain": ["plain"]`), имеющем общее ребро с рекой, со 100-процентной вероятностью:

```json
"spawn_conditions": [ [ { "type": "near_river", "chance": 100 } ] ]
```

#### `data/terrains.json` — типы местности (рельеф)

Корневой ключ: `terrains` (массив объектов).

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `id` | string | Уникальный идентификатор рельефа | `"plain"` |
| `name` | string | Отображаемое название | `"Равнина"` |
| `color` | array\<number\> | Цвет-заглушка RGB `[r, g, b]` (0–255) | `[144, 238, 144]` |
| `move_cost` | number | Стоимость перемещения | `1` |

#### `data/covers.json` — покров (растительность)

Корневой ключ: `covers` (массив объектов).

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `id` | string | Уникальный идентификатор покрова | `"forest"` |
| `name` | string | Отображаемое название (показывается игроку, напр. «Лес») | `"Лес"` |
| `color` | array\<number\> | Цвет-заглушка RGB `[r, g, b]` (0–255) для фолбека | `[34, 139, 34]` |
| `alpha` | number | Непрозрачность оверлея (0.0 – 1.0) | `0.45` |
| `move_cost_bonus` | number | Дополнительная стоимость перемещения от покрова (сейчас 0 — лес не замедляет, как раньше terrain-лес с `move_cost: 1`) | `0` |
| `icons` | array\<string\> | Иконки оверлея в `icons/terrain/` (рисуются поверх terrain; если пусто — цветной полигон) | `["forest_1.png", "forest_2.png", "forest_3.png"]` |

Используется в `resources/*.json` (поле `allowed_cover`).

#### `data/special_actions.json` — спецдействия на карте

Спецдействия — это действия, выполняемые на гексах карты (вырубка леса, сбор дикоросов, снос улучшений и т.п.). Они реализуются через систему труда `build_manager`, но не являются улучшениями.

Корневой ключ: `special_actions` (массив объектов).

| Поле | Тип | Обязательность | Описание | Пример |
|---|---|---|---|---|
| `id` | string | ✅ | Уникальный идентификатор спецдействия | `"clear_forest"` |
| `name` | string | ✅ | Отображаемое название | `"Вырубка леса"` |
| `action_type` | string | ⬜ | Тип действия. `"terrain"` (по умолчанию) — превращает местность; `"cover"` — меняет покров; `"forage"` — сбор ресурса; `"demolish"` — снос улучшения | `"cover"` |
| `source_terrain` | string | ⬜ | Для `action_type: "terrain"`. Тип местности, к которому применимо действие (см. `terrains.json`) | `"swamp"` |
| `source_cover` | array\<string\> | ⬜ | Для `action_type: "cover"`. Покровы, к которым применимо действие (см. `covers.json`). Действие недоступно, если на гексе есть ресурс или улучшение | `["forest", "sparse_forest"]` |
| `target_resource` | string | ⬜ | Для `action_type: "forage"`. ID ресурса, который собирается действием | `"wild_food"` |
| `result_terrain` | string | ✅ | Тип местности, в который превращается исходная. Значение `"dont_change"` означает, что тип местности не меняется | `"plain"`, `"dont_change"` |
| `result_cover` | string | ⬜ | Для `action_type: "cover"`. Покров, который будет установлен после завершения (например, `"none"` — вырубка леса) | `"none"` |
| `work_cost` | number | ✅ | Стоимость в труде | `22` |
| `yield` | object | ⬜ | Для `action_type: "forage"`. Что даёт действие: `{ "продукт": [мин, макс] }` — случайное количество в диапазоне | `{ "foraged_food": [5, 10] }` |
| `unlock_tech` | string | ⬜ | Технология, открывающая действие. Пока не изучена — в контекстном меню показывается пункт «Изучить X» | `"metal_processing"` |

**Типы действий (`action_type`):**

- `"terrain"` (по умолчанию) — превращает один тип местности в другой. Применимо, если гекс имеет `source_terrain` и на нём нет улучшения. Пример: осушение болот.
- `"cover"` — меняет покров гекса (`source_cover` → `result_cover`). Применимо, если `cover` гекса входит в `source_cover` и на гексе **нет** ресурса и улучшения (запрет вырубки леса с ресурсом/улучшением). При завершении меняется только `cover`. Пример: вырубка леса.
- `"forage"` — сбор ресурса (например, дикоросов). Применимо, если на гексе есть ресурс `target_resource`. При завершении убирает ресурс и добавляет `yield` на склад. Тип местности не меняется.
- `"demolish"` — снос улучшения. Применимо, если на гексе есть улучшение. При завершении убирает улучшение, ресурс остаётся. Тип местности не меняется.

> **Пример добавления нового спецдействия** (осушение болот): достаточно добавить запись с `"action_type": "terrain"`, `"source_terrain": "swamp"`, `"result_terrain": "plain"` и нужной стоимостью — код менять не нужно.
>
> **Пример сбора дикоросов** (встроен в игру): `"action_type": "forage"`, `"target_resource": "wild_food"`, `"result_terrain": "dont_change"`, `"yield": { "foraged_food": [5, 10] }`.
>
> **Пример сноса улучшения** (встроен в игру): `"action_type": "demolish"`, `"result_terrain": "dont_change"`.

#### `data/bonuses.json` — бонусы за разнообразие

Корневые ключи: `group_bonuses` и `subgroup_bonuses` (массивы объектов).

**`group_bonuses`** — бонусы за количество подгрупп в группе:

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `group_id` | string | ID группы (см. `groups.json`) | `"meat_animals"` |
| `bonus_type` | string | Тип бонуса | `"happiness"` |
| `tiers` | array\<object\> | Пороги бонуса | см. ниже |

**`subgroup_bonuses`** — бонусы за количество видов в подгруппе:

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `subgroup_id` | string | ID подгруппы (см. `groups.json`) | `"cattle"` |
| `bonus_type` | string | Тип бонуса | `"happiness"` |
| `tiers` | array\<object\> | Пороги бонуса | см. ниже |

**Объект `tiers`:**

| Поле | Тип | Описание | Пример |
|---|---|---|---|
| `min_subgroups` / `min_species` | number | Минимальное количество подгрупп (для `group_bonuses`) или видов (для `subgroup_bonuses`) | `3` |
| `value` | number | Величина бонуса | `10` |

## Миграция старых сохранений

При загрузке старого сейва (где `terrain` мог быть `"forest"`):

- `terrain == "forest"` → `terrain = "plain"`, `cover = "forest"`;
- иначе → `cover = "none"`.

Это выполняется в `main_map.gd` при восстановлении `tile_data`.
